# 多夥伴商店規格（生態廚師夥伴代銷）

> 此為佑在幹嘛時期的紀錄：生態廚師是佑在幹嘛的實際商業夥伴，跟問爽的無關。
> 程式機制（多夥伴出貨工作台、月結代銷）是通用的，問爽的如果要開多夥伴商店可以參考，
> 但商業條件（策展身分、稅務協議）要重談，不能沿用生態廚師那份。

觸發指令：**「製作多夥伴商店」**。2026-08-29 經三輪拷問＋外部實務查證定案。
本文件是規格，不是已完成的功能。動工前先確認資料表現況。

## 一、這是什麼生意（定性，全部施工都從這裡推導）

生態廚師夥伴的**自有產品**，掛「佑在幹嘛×生態廚師」策展身分販售。
法律性質是**受託代銷**：發票由本站開給消費者（需註明「受託代銷」字樣），
金流本站統一收款，**月結**發放貨款給夥伴（國稅局規定代銷結帳不得超過兩個月）。
消費者面對的是一個商店，但包裹由各夥伴自己的出貨地分別寄出，不集貨。

蛋捲模式是原型：站長後台有統計、夥伴收下單通知、夥伴有出貨工作台逐筆出貨。
這次把「夥伴」從隱含的一位變成一等公民。

## 二、動工前的站長功課（擋在所有程式之前）

1. **稅籍盤點**：逐一確認每位夥伴有無稅籍、能否開發票或收據給本站，
   拿答案問記帳士「小規模營業人的代銷怎麼處理」。答案寫進合作協議。
2. **食品合規硬門檻**：食品業者登錄、產品責任險、包裝負責廠商標示、
   效期承諾（收到時至少剩 N 天），文件齊才上架。站長把自己辦過的
   流程寫成一頁教學給夥伴（把門檻變成服務）。
3. **書面合作協議**（可用陳式設計簽約系統），必載：
   個資保密與顧客名單不得挪用、檔期專屬庫存承諾、超商退回件七日內
   領回並回報、貨損對半、結算後退款自下期貨款扣回、常溫／冷鏈屬性、下架權。
4. **隱私權政策第五條**補「出貨協力」類別（lib/legal-v2.ts＋遷移）。

## 三、資料模型

### 新增 `partners`

| 欄位 | 說明 |
|---|---|
| `id` / `name` | 夥伴名稱（例：○○工坊） |
| `key` | 工作台連結金鑰，一人一把，重生成只失效自己 |
| `pin` | 工作台密碼，一人一組 |
| `notify_emails` | 下單通知信箱（只收自己商品的通知） |
| `ship_origin` | 出貨地備註（結帳頁「此包裹來自○○」顯示用） |
| `active` | 停用＝工作台與通知全關，商品需轉移或下架 |

**本店也是一個出貨地**：partner_id NULL＝站長自己出（T恤、帆布袋…）。

### `products` 加欄位

- `partner_id`（NULL＝本店）
- `temp_zone`：`ambient`（常溫）／`cold`（冷鏈）。**第一檔期只收常溫夥伴**，
  但溫層與費率從一開始就進系統。

### 遷移

- 現有蛋捲商品 → 建立蛋捲夥伴並歸屬之；其餘商品 partner_id NULL。
- 舊的全域 `partner_key`／`partner_pin` 於切換部署即作廢（站長指示：
  本機驗完才推，一推舊連結立即失效，當天發新連結）。
- **orders 表完全不動**。訂單品項是快照，夥伴歸屬靠 product id 對照，
  既有訂單、運費、出貨記錄原樣保留。

## 四、運費：出貨地 × 溫層

- 購物車按（出貨地, 溫層）分組，每組一個包裹、收一次運費。
  同夥伴的常溫＋冷凍也是兩包兩費（本來就不能同箱）。
- 費率全站統一，settings 可改：常溫宅配 120／超商 65／**冷鏈宅配 160**
  （站長指示先用 160，後台可調）。冷鏈不走超商。
- 免運門檻（1440）**各組各自算**，各組小計達標該組免運。
- 後台開關「運費模式：按出貨地計運 ⇄ 全站單一運費」，保留切回今日模式的路。
- 結帳頁明細逐組列出：「包裹一（○○工坊，常溫宅配）：運費 120」，
  並在跨出貨地時顯示「你的訂單將由不同工坊分別寄出，包裹會分批送達」。

## 五、出貨工作台（每夥伴一個）

- `/partner/[key]` 概念：各夥伴只看到自己商品的訂單列。
  現有逐品項出貨旗標、逐批出貨通知信、多地址逐收件人機制全部沿用。
- 顯示**份數統計**（待出、已出、待付款參考、已保留參考），**不顯示金額**。
- 逾期未出警報：出貨週結束仍有未標出貨的單 → 自動寄信給該夥伴＋站長
  （掛在既有 15 分鐘對帳排程）。
- 售後（破損補寄、退換）一律回站長人工協調，工作台不做補寄功能。
- 個資最小化：顯示姓名、電話、地址（出貨必要），不顯示 Email。

## 六、企業訂購／付款連結

- **門檻改為 30 盒起**，30 盒以下走一般訂購（企業頁文案已於 2026-08-29 改）。
- **一條付款連結限單一出貨地的商品**（多地址名單掛在整筆訂單上，
  拆不了兩個夥伴各出一半；企業單單獨處理，站長指示接受此限制）。

## 七、通知與信件

- 下單通知：夥伴只收自己商品的；站長 `notify_emails` 維持全收。
- 出貨通知信（給顧客）沿用逐批寄送。
- 寄件人規範（寫進協議與夥伴教學）：包裹寄件人「佑在幹嘛×○○工坊」、
  聯絡電話填站長客服電話、退貨地址填夥伴出貨地。

## 八、結算報表（站長後台）

- 每夥伴 × 日期區間：商品銷售額、份數、該夥伴包裹收到的運費、
  退款訂單負項沖銷、（參考欄）含其商品的訂單帶進多少加購支持。
- 加購支持歸站長，不拆帳。
- 月結；結算後才發生的退款自下期扣回。可匯出 CSV。
- 商品刪除已改為「有訂單或連結引用即禁止、自動轉下架」（2026-08-29 已上線），
  這是報表可追溯性的前提。

## 九、消費者端

- 訂單查詢頁改**逐包裹狀態**（蛋捲：已寄出／梅子酥：準備中）。
  資料層（逐品項 shipped）已支援，純顯示施工。
- 商品頁必含效期資訊：列入上架文件清單的必填項，寫在現有規格表，不加欄位。
- 商品頁可標示出貨工坊（站長逐商品決定要不要露出）。

## 十、明確不做／已否決

- 集貨出貨（貨不在同一地，做不到）
- 夥伴自訂運費、夥伴看零售額、夥伴自助補寄、夥伴自己編輯商品內容
- 免運門檻全車合併計算（失血口）
- 出貨週的日期自動解析（沿用手動維護的既有決策）
- 第一檔期收冷凍夥伴（費率先建好備用）

## 十一、施工順序（每批本機驗完、站長過目才推）

1. **批次一**：partners 表＋products 加欄位＋遷移（蛋捲歸戶）。零行為變化。
2. **批次二**：工作台 per-partner 化＋金鑰切換（推這批的當下舊連結失效，
   站長當天發新連結）＋per-partner 下單通知。
3. **批次三**：運費引擎（出貨地×溫層、各組免運、後台開關與費率設定、
   結帳頁分組明細與分批送達提示）。
4. **批次四**：結算報表＋逾期未出警報＋訂單查詢逐包裹狀態。

每批 `npm run smoke` 加對應純邏輯測試（運費分組、免運判定、歸戶對照）。
