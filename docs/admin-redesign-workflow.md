這份是流程，不是設計稿。每一步的產出與「要站長點頭的地方」都寫死，避免又變成邊寫邊調。

## 站長已拍板的三條

1. **每頁乾淨**：一頁只做一件事，寧可多點一下。
2. **入口可以多，但要分類好，不要都塞進「更多」。**
3. **品牌不動**：CIS（米袋黃、朱紅、織帶、襯線標題、點點動畫）一條不改，只改操作層。見 memory `admin-ui-keep-cis`。

## 流程（六步，三個站長關卡）

進度（2026-09-06）：第 1 到 5 步完成，六批頁面全部上線（見 git log 2026-09-05 到 09-06）。第 6 步收尾未做：沒人用的 class 清理、videos 頁單一儲存列。

### 第 1 步　盤點與截圖（Claude 自己做）
- 用瀏覽器擴充在 390px 寬度逐頁截圖，存到 `docs/admin-redesign/before/`。
- 每頁寫一行「這頁該做的一件事」與「現在多出來的事」。
- 產出：`docs/admin-redesign/inventory.md`。
- 這步不需要站長，但截圖要給他看，讓他用同一組畫面跟之後的 after 比。

### 第 2 步　資訊架構（站長關卡 A）
- 重排側欄：入口數量不減，改成「幾組、每組主入口 + 次入口」的兩層結構，手機底欄放五個最常用。
- 決定哪些頁要拆：settings 拆成分頁（商店、贊助、金流、通知、內容、系統）；orders/[id] 改成「狀態與下一步」在上、資料在下、危險動作收到最底。
- 產出：一張文字版站點地圖 + 每頁的「一件事」。
- **拿給站長挑**，他點頭才進第 3 步。這一步用文字就好，不畫圖，改起來便宜。

### 第 3 步　畫布設計（站長關卡 B）
- 用 `/design` skill 開一張畫布，畫四個關鍵畫面的手機版與桌機版：總覽、訂單列表、訂單詳情、網站設定（其中一個分頁）。
- 設計 token 先定死：三層間距（8/14/24）、三個字級（標題 16、內文 14、副文 12，沿用 admin-ui-spec 的 13/12/12 再收斂）、三層灰、一個強調色（朱紅只給主動作與危險）。
- 元件只做這幾個：頁首（標題＋一顆主動作）、狀態條、卡片、鍵值表、開關列、篩選列、空狀態、危險區。其他都用這幾個拼。
- **站長在畫布上直接改**，改到滿意說「照這個做」才進第 4 步。

### 第 4 步　落地成設計系統（Claude 自己做）
- 把 token 寫進 `app/admin/(panel)/admin.css` 最上面成 CSS 變數，舊的散落數值全部改引用變數。
- 元件放 `components/admin/`：PageHead、StatusBar、Card、KV、SwitchRow、FilterBar、Empty、DangerZone。既有的 Switch、Check、ViewToggle、RemindButtons 保留並套 token。
- 更新 `docs/admin-ui-spec.md` 成新版規格，舊條目刪掉不留兩套。
- 先做一頁當樣板（訂單詳情），本機給站長看，沒問題再鋪全站。

### 第 5 步　逐頁套用（分批，每批一次站長關卡 C）
- 順序：訂單詳情 → 訂單列表 → 總覽 → 設定分頁 → 贊助 → 提醒 → 發送 → 其餘。
- 每批做完：390px 截圖存 `docs/admin-redesign/after/`，與 before 並排，附「改了什麼」一段話，等站長說推。
- 每批都要跑：tsc、smoke、build，加上用瀏覽器擴充在 390px 與 1280px 各開一次確認沒有橫向捲軸、沒有文字交疊。

### 第 6 步　收尾
- 刪掉沒人用的 class 與 inline style（grep `style={{` 數量要比 before 少一半以上，否則沒收乾淨）。
- memory 更新：`admin-ui-keep-cis` 加一行指到新版 spec。

## 自我檢查清單（每一頁套完都要過）

- 這頁只做一件事？頁首一句話說得出來？
- 主動作只有一顆？危險動作在最底且有確認？
- 手機 390px：沒有橫向捲軸、表格是卡片、按鈕高度 44 以上、開關對齊文字第一行。
- 字級只出現三種？間距只出現三種？
- 沒有新的 inline style？沒有新發明的 class？
- 空狀態有一句話而不是空白？
- 品牌元素一個都沒動？

## 不做的事

- 不換字型、不換配色、不換 logo。
- 不引入 UI 框架（Tailwind、shadcn 之類），現有 CSS 變數與元件就夠。
- 不在沒有站長關卡的情況下推任何一頁上線。
